# Design: CLI Paper End-to-End Journey

## Technical Approach

Single hermetic pytest gate (`tests/test_cli_paper_e2e.py`, `unittest` + `tmp_path`) drives `init --no-npm → status → ingest → deliberate → implement → remote → run --dry-run → audit` in one workspace. Boundaries faked: stubbed download/extract, `FakeAdapter` + fake `kaggle` on `PATH`, `--no-npm` + prebuilt `node_modules`. Thin `scripts/cli-paper-smoke.sh` reuses fixtures. Test-only; `cli.py`, `core/`, `bridges/` exercised, never changed. Gaps exposed as findings only.

## Architecture Decisions

| Option | Tradeoff | Decision |
|---|---|---|
| In-process `main([...])` per leg vs subprocess `papersmith` CLI | In-process is fast, debuggable, matches `test_papersmith_init.py`; subprocess proves packaging but adds flake/cost | In-process `main()` for every leg; subprocess only in smoke wrapper |
| Deep stub (fake Marker module) vs shallow stub (patch `_download` + extract fn, write canned `.md`) | Deep stub is faithful but pulls torch/surya; shallow stub is hermetic and <20 lines | Shallow stub: `mock.patch` download + extract, write canned `.md` with LaTeX + 1 figure ref |
| Reuse `FakeAdapter` (in `test_remote_execution.py`) vs new fake | Reuse proves seam generality; new fake duplicates 6-op contract | Import/replicate `FakeAdapter`; fake `kaggle` exe is a `#!sh` `exit 0` stub prepended to `PATH` |
| Commit tiny fixture PDF vs generate bytes in-test | Committed PDF is realistic; generated bytes avoid binary drift | Commit 1-page `tests/fixtures/e2e/paper.pdf` (<10KB) + canned `.md` expectation |
| Real consent/gate token vs pinned smoke/dry-run paths | Real token would spend quota and need launch authorization | Pin `--smoke` / `--dry-run` only; assert live `submit` without `--consent` refuses before adapter call |

## Data Flow

    tmp_path/ws ← init --no-npm (+ prebuilt node_modules link)
        → status (ready / dirty-fails-fast)
        → ingest (fixture PDF + stubbed extract → paper/*.md + fig)
        → deliberate init/status (managed r01, no model call)
        → implement verify/probe (target venv, no notebook exec)
        → remote pack/status (FakeAdapter + fake kaggle on PATH → job/ + ledger fold)
        → run --dry-run (plan only) → audit + drift probe (findings only)

Workspace topology under `tmp_path`: `guidance/reference-papers/<slug>/`, `proposals/`, `implementations/<repo>/`, `tools/kaggle/<job>/`, `.remote-execution/ledger.jsonl`.

## File Changes

| File | Action | Description |
|---|---|---|
| `tests/test_cli_paper_e2e.py` | Create | Journey suite (<800 lines), per-leg classes + hermeticity guards |
| `tests/fixtures/e2e/paper.pdf` | Create | 1-page fixture PDF + canned `.md` expectation |
| `scripts/cli-paper-smoke.sh` | Create | Thin wrapper: init/status/ingest/dry-run/audit reusing fixtures |
| `openspec/config.yaml` | Modify | Register `e2e: pytest test_cli_paper_e2e.py` layer |
| `src/papersmith/cli.py`, `core/`, `bridges/` | Referenced | Exercised only; zero production edits |

## Interfaces / Contracts

Helpers inside the test file (no new prod API): `_make_workspace`, `_stub_extract`, `_fake_kaggle_bin` (PATH-prepend), `_link_node_modules`. Per-leg assertions: exit codes + artifact existence + stdout markers (revision id, job folder, `dry-run: no job was dispatched`, audit finding). Guard: `socket.socket` patched to refuse; `KAGGLE_*` stripped.

## Testing Strategy

| Layer | What to Test | Approach |
|---|---|---|
| Unit | Stub helpers (extract stub writes `.md`; fake exe reachable) | Direct helper tests in same file |
| Integration | Each leg exit 0 + artifact; dirty-status non-zero; live-submit refuses | In-process `main([...])` with `mock.patch`, `tmp_path` isolation |
| E2E | Full init→audit green offline; `npm run test:all` green, suite <800 lines | Ordered journey test + `wc -l` budget check; 5 node e2e legs untouched |

## Threat Matrix

## Migration / Rollout

No migration required. Test-only; rollout is registration in `test:all`. Rollback: delete test file, fixture, smoke wrapper; revert `config.yaml`.
